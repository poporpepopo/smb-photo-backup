# 実機での確認手順

各フェーズで、実機（Pixel）とルーター（ASUS、USBストレージをSMB共有）を使って確認する項目です。

## 準備（共通）

```sh
export JAVA_HOME=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home
./gradlew assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

- スマホは家のWi-Fiにつなぐ
- ルーター側：USBストレージの「ネットワークプレース（Samba）共有」を有効にし、共有名とアカウントを確認しておく

## フェーズ1：設定画面と接続テスト

| # | 操作 | 期待する結果 |
|---|---|---|
| 1 | アプリを起動 | 設定画面が出る。端末の言語が日本語なら日本語表示 |
| 2 | IP・共有名・ユーザー名・パスワードを入れて「接続テスト」 | 「//IP/共有名 に接続できました」と、共有直下のフォルダ一覧が出る |
| 3 | 保存フォルダに存在しない名前（例 `Backup/Pixel`）を入れて「接続テスト」 | 「まだありません。最初の送信時に作成します」と出る（この時点ではフォルダを作らない） |
| 4 | 保存フォルダに `/Backup//Pixel/` と入れて「保存」 | 欄が `Backup/Pixel` に整形される |
| 5 | 「保存」→ アプリを最近使ったアプリから終了 → 再度起動 | 入力内容が残り、パスワード欄の下に「保存済み（変更するときだけ入力）」と出る。パスワード自体は表示されない |
| 6 | 5のあと、パスワード欄は空のまま「接続テスト」 | 2と同じく成功する（保存済みパスワードの復号が効いている） |
| 7 | パスワード欄にわざと違う値を入れて「接続テスト」 | 「ユーザー名かパスワードが違います」 |
| 8 | 共有名を存在しない名前にして「接続テスト」 | 「その名前の共有はありません」 |
| 9 | Wi-Fiを切ってモバイル通信だけにして「接続テスト」 | 1〜2秒で「445番ポートに届きません…」（長く固まらない） |
| 10 | 下の「ログ確認」 | パスワードが1件も出てこない |

### ログ確認（パスワードが出ていないこと）

7でわざと入れた値（例 `wrongpass`）で検索します。本物のパスワードはコマンドラインに打たないでください。

```sh
adb logcat -d | grep -c wrongpass           # 0 であること
```

### 保存データ確認（平文で保存されていないこと）

```sh
adb shell run-as io.github.poporpepopo.photobackup \
  cat files/datastore/settings.preferences_pb | strings
```

`password_enc` の値が意味のない英数字（Base64）で、パスワードそのものが見えないこと。

## フェーズ2：写真・動画の取得と1件送信

ホーム画面の「テスト：1件だけ送信」は、追加日時がいちばん新しい1件を送ります（フェーズ3で全件同期に置き換えます）。

| # | 操作 | 期待する結果 |
|---|---|---|
| 1 | 初回起動 | 「写真へのアクセス」が赤いカードで出て、「アクセスを許可」ボタンがある |
| 2 | 「アクセスを許可」→「一部のみ許可（限定アクセス）」で数枚だけ選ぶ | 「選択した写真と動画のみ…それ以外はバックアップされません」と出て、「すべて許可する」「アプリの設定を開く」が出る。件数は選んだ枚数になる |
| 3 | 「すべて許可する」→「すべて許可」 | 「すべての写真と動画にアクセスできます」になり、カードが赤でなくなる。件数がギャラリーとおおむね一致する |
| 4 | 位置情報をオンにしてカメラで1枚撮影 →「最新の1件を送信」 | 進捗が出たあと「Backup/Pixel/2026/10/PXL_….jpg に送信しました」（年/月は撮影日） |
| 5 | 4のファイルをPCで開く | 正常に表示される。撮影場所（GPS）が残っている（Macなら `mdls -name kMDItemLatitude -name kMDItemLongitude ファイル`） |
| 6 | もう一度「最新の1件を送信」 | 「同じ内容のファイルが…にすでにあります」。共有側に重複は増えない |
| 7 | 共有側で4のファイルを別の写真で上書き（同じ名前のまま）→ 送信 | 「…PXL_… (1).jpg に送信しました」。上書きしたファイルはそのまま残る |
| 8 | 30秒以上の動画を撮影 → 送信 | 進捗バーが進み、完了後にPCで再生できる。サイズがスマホ側と一致する |
| 9 | 8の送信中にWi-Fiを切る | エラーが出る。共有側に本来の名前のファイルはできていない（隠しファイル `.photobackup-<数字>.part` は残ってよい） |
| 10 | Wi-Fiを戻して再送信 | 完了し、`.part` ファイルは消えている（同じ名前の一時ファイルを上書きして使い、最後にリネームするため） |
| 11 | ギャラリーアプリで、送った写真・動画がスマホに残っていることを確認 | 削除も変更もされていない |
| 12 | `adb shell pm revoke io.github.poporpepopo.photobackup android.permission.ACCESS_MEDIA_LOCATION` のあとアプリを開く | 「位置情報へのアクセスを許可してください」と出て、送信は「先に写真と位置情報へのアクセスを許可してください」で止まる。「アクセスを許可」で戻る |

### 動画を撮らずに大きいファイルで確かめたいとき

```sh
# 200MB のダミー動画を置いてスキャンさせる（試したら消す）
adb shell "dd if=/dev/urandom of=/sdcard/Movies/test_big.mp4 bs=1M count=200"
adb shell am broadcast -a android.intent.action.MEDIA_SCANNER_SCAN_FILE -d file:///sdcard/Movies/test_big.mp4
# 後片付け
adb shell rm /sdcard/Movies/test_big.mp4
```

中身が乱数なのでプレーヤーでは再生できませんが、転送・サイズ確認・リネームの動きは確かめられます。

## ルーターなしで試す（Mac）

`tools/smb_test_server.py` に、Python 製のテスト用 SMB サーバーの起動方法を書いています。

- JVM：`SMB_TEST_PORT` と `SMB_TEST_ROOT` を付けて `./gradlew testDebugUnitTest` を実行すると、`SmbIntegrationTest` が実際に送信します（付けないときはスキップ）
- エミュレータ：`adb reverse tcp:445 tcp:4450` をしてから、アプリの設定を 127.0.0.1 ／ USB ／ tester にする

テスト用サーバーは一部の応答が Samba と違うので、最終確認は必ずルーターで行ってください。

## フェーズ3：送信済み管理と全件の手動同期

ホーム画面の「バックアップ」カードに「送信済み ○ 件・未送信 ○ 件」と「今すぐ同期」が出ます（フェーズ2の「1件だけ送信」は無くなりました）。

| # | 操作 | 期待する結果 |
|---|---|---|
| 1 | 起動 | 「送信済み 0 件・未送信 N 件」。N はギャラリーの写真＋動画の数（動画スイッチがオフなら写真のみ） |
| 2 | 「今すぐ同期」 | 「3 / N：ファイル名」と全体の進捗バー、ファイルごとのバイト数が進む。終わると「送信 ○ 件・既にあり ○ 件・失敗 0 件」 |
| 3 | フェーズ2で送った写真があれば | それらは「既にあり」に数えられ、共有側に重複は増えない |
| 4 | 共有をPCで見る | `<保存フォルダ>/年/月/` に撮影月ごとに入っている。`.part` ファイルが残っていない |
| 5 | もう一度「今すぐ同期」 | 「すべて送信済みです。」 |
| 6 | アプリを終了して起動し直す | 件数が保たれている（送信済みの記録が残っている） |
| 7 | 写真を1枚撮る → アプリに戻る | 「未送信 1 件」になり、同期でその1枚だけ送られる |
| 8 | Googleフォトなどで写真を編集して保存 → 同期 | 編集後の版が送られる。同じ月のフォルダに元の名前があるので `名前 (1).jpg` で保存され、元の版も残る（「コピーとして保存」なら新しい写真として送られる） |
| 9 | 大きい動画の送信中にWi-Fiを切る | すぐ〜最大30秒ほどで「ルーターとの接続が切れました。次の同期で続きから送ります。」。それまでに送れた分は送信済みに数えられている |
| 10 | Wi-Fiを戻して同期 | 残りだけが送られ、途中だった動画も完成する。`.part` は残らない |
| 11 | 設定で「動画もバックアップする」をオフ → ホーム | 件数が写真のみになり、「（動画は対象外）」と出る |

## フェーズ4：自動同期と通知

「今すぐ同期」も裏で動くようになり、アプリを閉じても続きます。結果はホームの「前回の実行」に残ります。懸念点と未確認の点は [open-issues.md](open-issues.md) の C6〜C11 です。

| # | 操作 | 期待する結果 |
|---|---|---|
| 1 | 新しいバージョンを入れて起動 | 数秒以内に定期実行の1回目が動き、ホームに「最終同期：（時刻）」と「前回の実行」が出る |
| 2 | Android 13 以上で通知を許可していない | ホームに「通知」カードが出る。「通知を許可」で許可するとカードが消える |
| 3 | 大きい動画を撮る →「今すぐ同期」→ すぐホームに戻る | 10秒ほどで「写真をバックアップしています」の通知が出て、「1 / N：ファイル名」と進捗バーが進む。終わると通知が消える。アプリを開くと「前回の実行」に送信件数が出ている |
| 4 | 写真を数枚撮り、アプリを開かずに1時間ほど置く（家の Wi-Fi） | 共有に届いている。アプリを開くと「最終同期」が更新されている。通知は出なくてよい（C6） |
| 5 | モバイル通信だけにして「今すぐ同期」 | 数秒で「ルーターに届きません。家のWi-Fiにつながっていますか？」。カードは赤くならず、「最終同期」の時刻はそのまま |
| 6 | モバイル通信だけのまま1時間ほど置く | 定期実行は動かない（「前回の実行」の時刻が変わらない） |
| 7 | 設定で「充電中のみ」をオンにして保存 → 充電器を外して写真を撮り、1時間ほど置く | 送られない。充電器をつなぐと、その後の回で送られる |
| 8 | 3の送信中に Wi-Fi を切る | 「ルーターとの接続が切れました…」で終わり、通知が消える。Wi-Fi を戻すと次の回で続きが送られる |
| 9 | 定期実行で送信中のとき（4の途中など）にアプリを開く | 進捗が出ていて、「今すぐ同期」は押せない（C11） |
| 10 | 一晩置いたあと、ホームの「最終同期」の時刻を見る | 朝の時点で1時間以内の時刻なら、夜中も動いている（C8） |
| 11 | フェーズ1の「ログ確認」をもう一度 | パスワードが出ていない |

### ジョブの状態を見る（adb）

```sh
# 定期ジョブの条件（NOT_METERED、charging=）と次の実行時刻
adb shell dumpsys jobscheduler | grep -A60 'JOB androidx.work.systemjobscheduler:u0a.*photobackup' | grep -E 'Requires|Network type|Run time'
# アプリの使用頻度のグループ（ACTIVE / WORKING_SET / FREQUENT / RARE / RESTRICTED）
adb shell am get-standby-bucket io.github.poporpepopo.photobackup
```
